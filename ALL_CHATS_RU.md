# Мониторинг всех чатов тестового аккаунта

В локальном config.ini в секции [monitor] установите all_chats = true.
Обязательный test_user_id должен совпадать с ID авторизованного тестового аккаунта.
При несовпадении мониторинг не запускается. Секреты задаются через переменные окружения;
config.ini, база сообщений и Telegram-сессия не должны попадать в Git.

Запуск из каталога проекта: bash start_monitor.sh
По умолчанию используется только сохранённая сессия, без нового входа.
Если требуется вход, программа завершится с TEST_LOGIN_REQUIRED.
Новая авторизация выполняется только по отдельному явному решению пользователя:
bash start_monitor.sh --authorize-test-account
Не используйте основной аккаунт. Для остановки запуска в терминале нажмите Ctrl+C.
Блокировка flock препятствует одновременному запуску двух экземпляров этого скрипта.
Не запускайте start_chat_id.sh одновременно с мониторингом: команды /id и /chatid
уже доступны в основном процессе.

Режим охватывает доступные аккаунту обычные чаты, включая новые чаты, каналы и сообщения ботов.
Служебный чат Telegram и личный чат с ботом уведомлений исключены.
Секретные и самоуничтожающиеся сообщения не сохраняются. Вложения не скачиваются;
обрабатываются текст и подписи. История до запуска автоматически не загружается.
Уведомление о правке или удалении возможно для сообщения, ранее сохранённого монитором.
Для возврата к одной тестовой группе установите all_chats = false и chat_ids = ID группы.

Codespaces может остановиться при простое; вместе с ним останавливается мониторинг.
После запуска Codespace снова выполните bash start_monitor.sh.
Для непрерывной работы требуется постоянно включённый сервер; этот запуск не гарантирует 24/7.

Проверка: python -m unittest test_monitor test_safety test_commands test_all_chats -q
Проверены 25 тестов и живой цикл отправки, правки и удаления собственного демо-сообщения
в тестовой группе. Bot API принял уведомления о правке и удалении.
