# Три аккаунта, отдельные уведомления

Новый режим запускается отдельно от прежнего main.py. Обновление кода само по себе
не подключает основной аккаунт, не переносит тестовую сессию и не начинает вход.
Работает на Linux (Codespaces или VPS). Для 24/7 нужен включённый сервер.

Один процесс принимает команды бота. Для каждого аккаунта запускается отдельный
процесс TDLib, своя сессия и SQLite-база в `.chat-monitor-accounts/<user_id>/`.
Получатель уведомлений всегда равен user_id авторизованного аккаунта;
отдельного общего получателя нет. Это изоляция данных приложением, а не защита
от администратора сервера: процессы работают под одним системным пользователем.

## Настройка

1. Остановите старый монитор перед запуском нового режима. Скрипты используют
   общую блокировку `.chat-monitor.lock`; не запускайте main.py вручную в обход неё.
2. Скопируйте `accounts.ini.example` в локальный `accounts.ini`, задайте путь к
   существующей библиотеке TDLib и числовые ID владельцев (от одного до трёх).
   Не оставляйте нули; удалите ненужные секции. Одинаковые ID запрещены.
3. Задайте секреты среды: `CHAT_MONITOR_BOT_TOKEN`, `CHAT_MONITOR_API_ID`,
   `CHAT_MONITOR_API_HASH`, а также `CHAT_MONITOR_FIRST_PHONE`,
   `CHAT_MONITOR_SECOND_PHONE`, `CHAT_MONITOR_THIRD_PHONE` для нужных секций.
   Номера — в международном формате. Имена FIRST/SECOND/THIRD соответствуют
   именам секций first/second/third. При необходимости 2FA задаётся через
   `CHAT_MONITOR_FIRST_PASSWORD` и аналогичные переменные, либо вводится скрыто
   в интерактивном терминале. Не помещайте секреты в исходники или Git.
4. Проверьте файл: `bash start_multi.sh --check`.
   Это только проверка структуры: без Telegram и без чтения секретов.
5. Каждый владелец отдельно разрешает и выполняет вход в свой профиль:
   `bash start_multi.sh --authorize first` (затем second и third по необходимости).
   Команда требует интерактивного терминала. QR/коды и пароли не передаются боту.
   Владелец должен проверить профиль перед подтверждением входа.
   Программа сверяет ID аккаунта; при несовпадении мониторинг не включается.
6. Все владельцы открывают личный диалог с ботом и нажимают «Запустить»,
   чтобы бот мог присылать им уведомления.
7. Запуск мониторинга: `bash start_multi.sh --run`.
   Остановка в терминале: Ctrl+C. В фоне запускать через менеджер служб сервера.

Без действующей сессии профиль получает статус «нужна авторизация» и не пытается
запускать вход самостоятельно. Остальные профили продолжают работать.
После отдельной авторизации перезапустите сервис. При сбое процесса он перезапускается
с задержкой 5–60 секунд; при неверной конфигурации, занятой сессии или несовпадении
ID автоматические попытки останавливаются. Живой, но зависший процесс после успешного
старта не выявляется этим механизмом; полноценный контроль доступности ещё не добавлен.

## Команды и доступ

В личном диалоге `/start`, `/status`, `/id`, `/chatid` показывают только собственный ID
и статус собственного профиля. Аргумент команды не позволяет выбрать другого владельца.
Незарегистрированный пользователь узнаёт только свой ID и порядок подключения;
ссылка не даёт доступа к чужим данным и не авторизует Telegram-сессию.
В группах эти команды в новом режиме не отвечают.

`enabled = false` исключает профиль из мониторинга после перезапуска сервиса.
Все доступные обычные чаты отслеживаются при `all_chats = true`.
Для ограничения задайте `all_chats = false` и список `chat_ids` через запятую.
Служебный чат Telegram и чат с ботом исключены, секретные чаты отключены.
Медиа не скачиваются, самоуничтожающиеся сообщения не сохраняются.
Для правки/удаления нужна ранее сохранённая версия сообщения; старая история не импортируется.
Записи старше 30 дней удаляются при запуске и далее раз в 6 часов.

## Проверки и ограничения

Офлайн-тесты: `python -m unittest test_monitor test_safety test_commands test_all_chats test_multi_account -q`.
Проверяется разделение трёх профилей даже при одинаковых ID чатов/сообщений,
маршрутизация уведомлений, запрет чужих статусов и отсутствие автоматического входа.
Живая проверка трёх сессий возможна после их отдельной авторизации владельцами.
Тестовая сессия старого режима остаётся отдельно; автоматической миграции нет.
Существующий webhook не удаляется: сервис откажется стартовать, если он настроен.
Без VPS и настройки службы запуск из Codespaces не обеспечивает круглосуточную работу.
